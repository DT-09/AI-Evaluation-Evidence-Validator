Transaction document control / Version intelligence

When a number changes, find where it travelled.

DealTie compares analyst-confirmed financial observations across successive document versions and maps exact downstream references that may still carry an earlier value. It is designed for M&A advisory, transaction advisory and financial diligence teams.

The problem

A revised Quality of Earnings report changes adjusted EBITDA. The old figure may remain in the CIM, management presentation or valuation model. Reviewers must find every affected reference before material is circulated.

What DealTie checks

  • Baseline and current versions of a source document family
  • Exact metric and period matches
  • Reported values and explicitly stated units
  • Other supplied documents carrying the same metric and period

How the output is classified

  • Stale candidate: downstream value matches baseline, not current
  • Aligned to current: downstream value matches the current version
  • Other value: downstream value matches neither
  • Insufficient evidence: values or units cannot be compared safely

What it does not assume

  • No semantic matching of differently named metrics
  • No currency, scale or period conversion
  • No automatic source-authority decision
  • No conclusion that a discrepancy is an error
EXAMPLE / SYNTHETIC ONLY
QoE v1: Adjusted EBITDA 18.2 → QoE v2: 17.6. A CIM still showing 18.2 is marked as a stale candidate for human review. A valuation model showing 17.6 is marked aligned to the current source value.
Important boundary. DealTie's version analysis compares analyst-confirmed observations using exact metric, period and unit matching. A stale candidate is an investigation lead, not proof of an error or misstatement. The current application is a prototype and is not a secure deal room. Do not upload confidential transaction files to the public workbench.
